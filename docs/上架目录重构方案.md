# HRX 资源库 · 上架目录（catalog）重构方案

适用工程：`Z001_网盘站点`（主站 pcpan.top，镜像 pages.dev / qoder.zone）
状态：**提案，待拍板**。本文只描述改造，不修改 `data/`、`web/` 里的现有内容。
一句话：把"扫描软件工程 → 拼页面"改成"维护一个上架目录 → 构建页面"，扫描器从"写数据"降级为"提候选"。

## 一、现状：数据、素材、正文分散在三处

### 1.1 现在的链路

```
../AI_SOFT/<数字_工程名>/          ../AI_WORD/W000_.../
        │ 扫描（--force 覆盖 12 个自动字段）        │
        ├──────────────► data/shares.yaml（11 条）   data/docs.yaml（1 条）
        │                        │
        │ 构建时现取封面           │ 构建时现取正文
        └──────────────► tools/build_site.py ◄──────┘
                                 │
                                 └──► web/（6 个页面）──► 三个发布地址
```

构建器对源工程的依赖是三处硬编码（`build_site.py`）：

| 依赖 | 位置 | 说明 |
| --- | --- | --- |
| 封面图 | `make_images(entries, jobs_root)` L1068，取 `root/slug/<image>` L223 | `image` 字段存的是**相对软件工程根目录的路径字符串**，不是站点自己的文件 |
| 详情页正文 | `load_manual(..., jobs_root)` L1076 → `manual.find_manual(root/slug)` L945 | 每次都去读 `用户手册/*使用说明.md`（4 篇 16~21 KB），正文不进版本库 |
| 文档封面 | `make_images(docs, docs_root)` | 同第一条，换成 AI_WORD |

### 1.2 五个体检结论（都有代码/数据可以指认）

1. **"要不要展示"是隐式的**：唯一闸门是"有没有挂链接"（`load_entries` L136-145）。
   结果：扫描到的新工程只要填了链接就自动上页；`shares.yaml` 里 7 条（002/003/004/005_Win窗口管家/007/008/010）
   因为没有链接，永远不渲染，却一直占着数据文件、每次扫描还被回写 `updated`。人想"先收着、别上网"没有任何字段可用。
2. **素材不是站点的资产**：封面存路径字符串、正文构建时现读。源工程换图、改名、删手册，下一次构建站点就跟着变；
   取不到时 `make_images` 只 `print` 一句 miss，卡片静默退化成排版封面（L221-228）。也就是说：**线上展示什么，取决于源工程当前长什么样，不取决于你发布时确认过什么。**
3. **构建离不开源工程**，这就是 README 里"GitHub 构建机没有 `../AI_SOFT`、`../AI_WORD`，所以不在 Cloudflare 侧构建、`web/` 必须入库"这条的根因。换机器、换盘符都得先摆好目录。
4. **扫描是"写数据"而不是"提候选"**：`--force` 重新生成 12 个自动字段（`AUTO_KEYS`，`scan_jobs.py` L107-121），
   人工改写过的 `summary`/`description`/`features`/`image` 会被抹平。所以"改过文案就别再扫"，这是维护负担的直接来源。
5. **目录名当主键会带来重号与漏登**：`005_WinButler窗口管家`（hidden）与 `005_Win窗口管家`（live 但无链接）
   是同一款软件的两条数据；AI_SOFT 现有 15 个工程，其中 011/012/013/014 根本没登记进数据文件。

**迁移成本很低**：已上架 4 条的封面原图 36~74 KB、手册 16~21 KB；`web/images` 全部 11 个文件 0.38 MB。
把素材收进版本库大约增加 1~2 MB（不含 `dist/*.zip`，发行包不进来）。

## 二、目标（写成验收条件）

1. `catalog/` 是唯一上架真源；**删掉 `../AI_SOFT`、`../AI_WORD` 也能重建出同样的站点**。
2. 展示资格显式：`status` 决定上不上页，链接只是条目里的一个字段。
3. "针对性替换"成立：换封面 = 覆盖一个文件；换链接 = 改一段或一条命令；换正文 = 改一个 md。都不需要全量扫描。
4. 人能用一张表看全：`catalog/index.csv` 可筛选、可排序、可发给别人，字段和页面一一对应。
5. 不伤 SEO：`slug` 与 `name_en` 不变 → 现有 6 个 URL（4 软件 + 1 资料 + 首页）全部不变，canonical/sitemap 照旧。
6. 可回滚：切换前打 git tag，改前改后产物逐文件比对。

## 三、三个方案，选 A

| 维度 | **A. 目录即真源（推荐）** | B. 只冻结素材，仍用 shares.yaml | C. CSV 当唯一真源 |
| --- | --- | --- | --- |
| 素材是否入库 | 是，每条目一个文件夹 | 是（`assets/` 平铺） | 是 |
| 条目字段 | 每条目 `meta.yaml`，短、可 review | 26 KB 单文件，改一行要滚 700 行 | 一张大 CSV |
| 多网盘渠道 | 天然列表 | 天然列表 | 要摊成 `url1/code1/url2/code2` 列 |
| 功能要点/关键词 | 列表 | 列表 | 无法表达层级，只能塞分号 |
| Excel 破坏值 | 不涉及（CSV 是导出视图） | 不涉及 | 提取码 `0101`→`101`、`1.29.10`→日期、长文本换行 |
| diff 可读性 | 一个条目一次改动，一眼看出改了什么 | 整段漂移 | 整行替换 |
| 构建脱源 | 完全脱源 | 完全脱源 | 完全脱源 |
| 取舍 | 需要新写一个 `catalog.py` | 改动最小，但"扫描写数据"的毛病留着 | 人人会用 Excel，但值会被破坏 |

**为什么不让 CSV 当真源**：Excel 会静默改四类值——前导零（提取码 `0101`、编号）、类版本号（`1.29.10` 认成日期）、
含逗号换行的长中文（需要引号转义，手改必错）、以及列表字段（`features` 只能写成 `a;b;c`，渲染时再拆，
一旦某个功能点里本来就有分号就崩）。再加上 CSV 的 diff 是"整行替换"，
改一个链接号在 review 里看不出来。所以：**CSV 做只读视图（`index.csv`），只在链接这一件事上给一张可往返的窄表**。

## 四、方案 A 详细设计

### 4.1 目录结构

```
Z001_网盘站点/
├─ catalog/                         # 上架目录：站点展示的唯一真源（进版本库）
│  ├─ index.csv                     # 自动导出：一条一行的总清单（只读视图，Excel 打开）
│  ├─ links.csv                     # 可选往返：一条渠道一行，供批量改链接（catalog.py links in/out）
│  ├─ 000_PDF超级工具箱/            # 目录名沿用原工程名 = slug，不改 → URL 不变
│  │  ├─ meta.yaml                  # 名称/版本/分类/状态/渠道/标签（人改这里）
│  │  ├─ manual.md                  # 详情页正文（原 用户手册/*使用说明.md 的副本，可手改）
│  │  ├─ cover.png                  # 卡片封面原图（构建统一转 webp）
│  │  ├─ detail.png                 # 详情放大图（可选）
│  │  └─ _source.json               # 来源记录，intake 时写，人不动
│  ├─ 001_证件照制作工具/
│  ├─ 006_图片去除水印工具/
│  ├─ 009_AI缓存专清/
│  └─ W000_WorkBuddy实战文档系列/    # 文档类同结构，meta 里 kind: doc
├─ site/                            # 前端源文件（不变）
├─ tools/
│  ├─ catalog.py                    # 新增：体检 / 导出 / 采集 / 刷新 / 链接 / 漂移
│  ├─ build_site.py                 # 改：只读 catalog
│  └─ scan_jobs.py scan_docs.py     # 降级：--report 只体检源工程，不再写数据
├─ data/paths.yaml                  # 只给 intake/drift 用，构建不再依赖
└─ web/                             # 构建产物（不变）
```

软件与文档**同层混放**，靠 `meta.yaml` 里的 `kind: soft|doc` 区分：目录名本身就是 `数字_` / `W000_`，一眼能分，
没必要多一层。slug 保持原样，`005` 重号问题在迁入时合并成一条（保留 `005_Win窗口管家`，另一条 `_source.json` 里记明曾用名）。

**和现在的差别**只有三点：`image` 变成 `cover`（指向本目录的文件，不再是源工程里的相对路径）；
正文从"构建时现取"变成"目录里的 `manual.md`"；`status` 之外多了 `draft`（收着但不展示，也不需要挂链接）。

### 4.3 `index.csv`（自动生成，只读）列定义

| 列 | 来源 | 用途 |
| --- | --- | --- |
| 目录 | 目录名 | 主键，排序/对照用 |
| 类型 | `kind` | 软件 / 资料 |
| 名称 / 英文名 / 版本 | meta | 核对 |
| 分类 | meta | 分类筛选栏就是它的去重结果 |
| 状态 | meta | 筛 `live` 就是线上那 5 条 |
| 渠道数 / 主渠道 / 主链接 / 主提取码 | 第一条 `downloads` | 人最常看的一列；提取码空着 = 还没填 |
| 封面 / 详情图 | 文件是否存在 | 显示 `✓ cover.png` 或 `缺` |
| 手册 | `manual.md` 是否存在 | 缺了详情页正文会偏薄 |
| 体积MB / 更新时间 | meta | 核对发行包、判断是否该重建 |
| 简介 | meta `summary` | 一眼看懂这条是什么 |

编码用 `utf-8-sig`（Excel 直接双击不乱码）。**这个文件任何手改都会在下次 `catalog.py index` 时被覆盖**，
文件头会写一行注释说明；真要批量改链接，走 `links.csv`。

### 4.4 状态机

| 值 | 页面表现 | 是否需要链接 |
| --- | --- | --- |
| `live` | 正常卡片 + 详情页 | 是（没链接时构建报错，而不是静默消失） |
| `coming_soon` | 灰卡"即将上架" | 是（占位链接） |
| `draft` | **完全不出现**，只在 `index.csv` 里 | 否 |
| `hidden` | 完全不出现，且不进 index.csv 的默认视图 | 否 |

这就把"扫描来的工程自动上网"这条口子关掉了：新采集进来的条目默认 `draft`，
你要它上页必须自己把 `status` 改成 `live`，顺带确认封面、正文、链接三样都在。

### 4.5 图片规范

- `cover.png`：16:9，宽度 ≥1280（构建按 `MAX_WIDTH=1280` 出卡片图、`MAX_FULL_WIDTH=1920` 出详情图，统一转 webp）。
  原图小于 1280 不会被放大，只做等比缩放，不二次劣化。
- `detail.png`：可选，宽度 ≤1920。没有就用 `cover` 当详情放大图（现状就是这样）。
- 图标类（003/007/008/010 那种 `resources/icon/app.png`）：`kind: icon` 标在 meta 里，构建出 128×128 的 PNG，走 `image_kind` 原逻辑。
- 素材只进 `catalog/<条目>/`，**发行包 `dist/*.zip` 永远不进库**（几十~两百 MB），meta 里用 `local_artifact` 指一下路径给人看就够了。

### 4.6 `tools/catalog.py` 命令清单

```bash
python tools/catalog.py check                       # 体检：必填缺失 / 封面不存在 / 链接格式 / slug 冲突 / 手册缺失
python tools/catalog.py index                       # 导出 catalog/index.csv
python tools/catalog.py intake 012_老照片修复工具     # 从 AI_SOFT 采集一条：拷封面+手册、填自动字段，status=draft
python tools/catalog.py refresh 001_证件照制作工具 --cover    # 只重取封面（针对性替换）
python tools/catalog.py refresh 009_AI缓存专清 --manual       # 只重取手册
python tools/catalog.py link 009_AI缓存专清 --platform 夸克网盘 --url https://pan.quark.cn/s/xxxx --code 1A2B
python tools/catalog.py links out                   # 导出 catalog/links.csv（一条渠道一行）
python tools/catalog.py links in                    # 从 links.csv 回写 meta（只动 downloads 这一段）
python tools/catalog.py drift                       # 与 AI_SOFT 源文件比对：源换图/改手册了，目录没跟 → 提示你 refresh
```

`drift` 是替代"每次全量扫描"的关键：它**只报告、不写**。`_source.json` 里记着当初从哪个文件抄的、
以及那个文件的 sha1，所以能精确说出"001 的封面在源工程里换了，要不要拉过来"。

### 4.7 构建侧改动（`build_site.py` 三处，约 60 行）

1. `load_entries(path)` → `load_catalog(catalog_dir)`：遍历 `catalog/*/meta.yaml`，
   kind 分软件/资料，`status` 过滤改成 `draft`/`hidden` 直接跳过；`live` 但没链接时**报错列出条目名**（现在是静默消失）。
2. `make_images(entries, root)` → 源改成 `catalog/<slug>/<cover>`，输出逻辑不变（名字仍按 slug 生成，产物文件名不变）。
3. `load_manual(entry, jobs_root)` → 读 `catalog/<slug>/manual.md`，`manual.parse` 的解析逻辑原样复用。
4. `resolve_roots` 与 `data/paths.yaml` 只留给 `catalog.py`，构建不再读，因此**构建可以在任意机器上跑**。
5. `site:` 段（品牌名、域名、公众号名、验证文件、tasks、indexnow）继续留在 `data/shares.yaml` 顶部太别扭，
   迁到 `catalog/site.yaml`，构建只读这一个站点级文件。

## 五、迁移步骤（三阶段，每阶段一个提交，随时可中断）

**阶段 0 · 打点**
`git tag pre-catalog`；备份现有 `web/` 到 `_snap/`（比对用，不入库）。约 5 分钟。

**阶段 1 · 灌入 + 对拍（不切源）**
1. 写 `tools/catalog.py`（`intake` / `index` / `check` 三个子命令先够用）。
2. `catalog.py intake` 跑 5 条已上架的（000/001/006/009/W000）：拷 `cover`、拷 `manual.md`、按现有 `shares.yaml`/`docs.yaml` 的字段生成 `meta.yaml`（**以现有数据为准，不做二次抽取**）。
3. `catalog.py index` 出 `index.csv`，和 `shares.yaml` 逐条对字段。
4. 此时构建仍走老路径，站点不变。
验收：`index.csv` 18 列×5 条与现有数据一致；`catalog.py check` 全绿。

**阶段 2 · 切源 + 清理**
1. 改 `build_site.py` 读 catalog；`python tools/build_site.py` 重建到 `web/`。
2. 对拍：`git diff --stat web/` 应只有 `lastmod`/`updated` 这类预期差异；
   `python tools/seo_check.py` 必须通过；`index.html` 卡片顺序、链接、封面文件 hash 一一对齐。
3. 删 `data/shares.yaml`、`data/docs.yaml`（git 里有历史，删了更干净），`site:` 段迁到 `catalog/site.yaml`。
4. `scan_jobs.py` / `scan_docs.py` 改 `--report` 模式（不再有写文件分支），避免"扫描改站点"再次发生。
5. 更新 `README.md`（目录结构、日常维护、部署三节）与 `AGENTS.md`（提交范围加 `catalog/`）。
验收：把 `../AI_SOFT` 与 `../AI_WORD` 临时改名后重建，产物必须与改名前一模一样——这一条就是"彻底脱源"的证明。

**阶段 3 · 补录（可选）**
`011_/012_/013_/014_` 用 `intake` 收进 catalog，全部 `draft`，等有链接了再改 `live`。
`005` 重号合并为一条；`002/003/004/007/008/010` 这些"有工程没链接"的也收进来，统一 `draft` 挂在 index.csv 上待办。

预计 1 个工作日：`catalog.py` 约 350 行，`build_site.py` 改 60 行，迁移与对拍 1~2 小时。

## 六、风险与回滚

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 图片入库让仓库变大 | 约 +1~2 MB | 只收封面/详情图，`dist/*.zip` 永不进库；必要时 `detail.png` 只保留有详情大图的条目 |
| URL 变化伤收录 | 5 条详情页 404 | `slug`、`name_en` 一个都不改；切源后跑 `seo_check.py` + 逐页访问 200 |
| 手册出现两份（catalog 内 / 软件工程内）漂移 | 站点正文落后于软件手册 | 规则写死：**站点以 catalog 为准**；`catalog.py drift` 提醒，人工 `refresh --manual` 才同步 |
| 有人把 `index.csv` 当真源改 | 改动被下次导出覆盖，白改 | 文件头注释 + README 明示；批量改链接走 `links.csv` 往返 |
| 迁完发现漏字段 | 页面缺块 | 阶段 1 保留老数据、双跑对拍，切源放到阶段 2；回滚 = `git reset` 到 `pre-catalog` tag |
| Excel 打开 links.csv 改提取码被打回数字 | 提取码错 | `links out` 导出时把 code 写成文本保护格式，`links in` 读回时剥掉；列固定 5 列不给自由发挥空间 |

## 七、需要你拍板的四件事（括号里是我的建议）

1. **CSV 的定位**：只读总览 + `links.csv` 专用往返（推荐），还是你就要"一张 CSV 全可改"（那要接受 Excel 破坏值，我另做校验兜底）。
